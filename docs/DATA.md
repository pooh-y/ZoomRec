# Data download and preprocessing

Use **Amazon Beauty 5-core (2014)**. The 2018 All_Beauty and 2023 releases have different records. ZoomRec reads the review JSON and product metadata to recover observed ratings, item content and event order. A ratings-only CSV lacks the required metadata. [McAuley Lab dataset description](https://mcauleylab.ucsd.edu/public_datasets/data/amazon/index_2014.html)

## Download

```bash
python prepare_data.py --download
```

The script verifies the SHA-256 digests before constructing item IDs and user histories. If a mirror provides different bytes, check the release and compression against the reference. [Expected file hashes](../configs/data_sources.json)

| File | Expected bytes | Source |
| --- | ---: | --- |
| `reviews_Beauty_5.json.gz` | 44,819,276 | [Stanford reviews archive](https://snap.stanford.edu/data/amazon/productGraph/categoryFiles/reviews_Beauty_5.json.gz) |
| `meta_Beauty.json.gz` | 99,156,148 | [Stanford metadata archive](https://snap.stanford.edu/data/amazon/productGraph/categoryFiles/meta_Beauty.json.gz) |

## Use existing files

The default data root is the sibling directory `../zoomrec_data/`. The nested `data/raw/` directory is part of the expected layout.

```text
../zoomrec_data/
├── data/raw/
│   ├── reviews_Beauty_5.json.gz
│   └── meta_Beauty.json.gz
└── freeze/                         # Generated by prepare_data.py
    ├── item_map.json
    ├── cards.json
    ├── categories.json
    ├── sequences.json
    └── data_manifest.json
```

Place the two archives in `data/raw/` under the data root and run `python prepare_data.py`. Set `ZOOMREC_DATA_ROOT` to use another data directory with the same layout.

Preprocessing keeps users with at least five interactions. It orders records by timestamp, ASIN and original row number, then assigns item IDs starting at 1 in sorted ASIN order. ID 0 is reserved for padding. The preprocessing code implements the title truncation, category extraction and token filters used in the experiment.

The reference data contains 22,363 users, 12,101 items and 198,502 interactions. Leave-one-out splitting gives 153,776 training interactions, 131,413 next-item training examples, 22,363 validation events and 22,363 test events.

`prepare_loo.py` writes training and evaluation inputs to `inputs/freeze/` inside the run directory. On the first run, `history_states.py` generates the Qwen summaries. The project distributes code separately from data, summaries and prompt logs. Git ignores their default directories.

Follow the dataset provider's usage and citation terms. The release excludes raw reviews, user IDs, title lists and complete product metadata.
